```csharp
// TARGET: two-probe strategy
private static string ResolveDefaultCliPath()
{
    // Probe 1: same folder as GUI exe (xcopy / zip install where both exes are co-located)
    var sameFolder = Path.Combine(AppContext.BaseDirectory, "InfoExeApp.exe");
    if (File.Exists(sameFolder))
        return sameFolder;

    // Probe 2: dev-layout sibling project (4 levels up from net10.0 output dir)
    // BaseDirectory = …\src\InfoExeGui\bin\Debug\net10.0\
    // 4 × ".." = …\src\
    var devLayout = Path.GetFullPath(Path.Combine(
        AppContext.BaseDirectory,
        "..", "..", "..", "..",               // ← 4 levels (CORRECT)
        "InfoExeApp", "bin", "Debug", "net10.0", "InfoExeApp.exe"));
    return File.Exists(devLayout) ? devLayout : string.Empty;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied CLI path | Text from CliPathBox is passed to ProcessStartInfo.FileName; must be an absolute path to a real exe |
| User-supplied folder paths | RootPathBox, SearchPathBox, DbPathBox — supplied values become subprocess arguments and directory operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Elevation of Privilege | `ProcessStartInfo.FileName` (CliPathBox value) | accept | This is a single-user desktop tool; the user explicitly selects the exe path via Browse picker or manual entry. No privilege boundary is crossed — the subprocess inherits the same user token. |
| T-06-04 | Tampering | `ResolveDefaultCliPath` probe 2 (relative path traversal) | accept | The relative path resolves inside the repo tree at dev time. No user-controlled input influences probe resolution; both probes are hard-coded relative segments. |
| T-06-05 | Denial of Service | OutputBox unbounded text accumulation (O(n²) string concat) | accept | Flagged in RESEARCH.md as a known limitation acceptable for Phase 6 scan-only scope. Very long scan output may cause UI slowness; acceptable until a future phase addresses it with a StringBuilder flush. |
| T-06-06 | Spoofing | Fake InfoExeApp.exe placed in same folder as InfoExeGui.exe | accept | Desktop app; user controls install layout. If malicious software can write to the install folder it already has sufficient privilege. The browse-button path selection gives explicit control. |
</threat_model>
