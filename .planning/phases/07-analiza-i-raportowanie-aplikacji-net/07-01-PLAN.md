# Phase 7 - Plan 01: Design report data model and schema extensions

## Objective

Extend the analysis report data model to capture comprehensive technology, dependency, license, and build information. Add schema extensions for dependency tracking and license detection.

## Requirements Covered
- ANALYZE-01: New `analyze` command generates structured analysis
- ANALYZE-02: Assembly metadata (name, version, target framework, references, signing)
- ANALYZE-03: Dependency graph and encoding detection

## Implementation

### 1. Data Model Extensions (`AnalysisReport`)

New fields:
- `TechnologyStack` — detected frameworks (.NET Framework, .NET Core, .NET 5+, Native)
- `LicenseSummary` — detected licenses (MIT, Apache-2.0, etc.)
- `BuildFiles` — list of build-related files found (.sln, .csproj, Dockerfile, CI/CD)
- `CodeMetrics` — lines of code, file count, project count from decompiled sources

New `AssemblyInfo` fields:
- `IsILOnly` — whether the assembly is pure IL
- `IsReadyToRun` — R2R compilation detected
- `IsNativeAot` — Native AOT compilation detected
- `Dependencies` — list of assembly references (name + version)
- `License` — detected license for this assembly
- `NuGetPackages` — NuGet package references found in decompiled .csproj

### 2. Schema Extensions

New table: `assembly_references`
- id, scan_file_id, referenced_assembly_name, referenced_version
- FK to scan_files

New table: `license_detections`
- id, scan_file_id, license_type, confidence, source_path

### 3. Data Flow

```
scan → DB (scan_files + assembly_metadata + vendor_results + decompilation_results)
     ↓
analyze → AnalysisReportBuilder
     → reads scan_files + assembly_metadata + vendor_results + decompilation + NEW references + licenses
     → builds AnalysisReport with technology detection
     → MarkdownReportFormatter / HtmlReportFormatter
     → output file
```
