# Phase 9 - Plan 01: GUI standalone with embedded logic and live progress

## Objective

Refactor InfoExeGui to run scan/analyze logic in-process (eliminating the subprocess dependency on InfoExeApp.exe). Add real-time progress bar, live output streaming, auto-detection of ILSpy and .NET SDK, and a seamless single-click workflow from folder selection to report viewing.

## Requirements Covered

- GUI-11: Embedded scan/analyze logic (no subprocess to CLI)
- GUI-12: Progress bar during scan
- GUI-13: Live output streaming during decompilation and analysis
- GUI-14: Auto-select scanId after scan for immediate report generation
- GUI-15: Open report button in default browser/app
- TOOLS-01: Auto-detect ILSpy installation path
- TOOLS-02: Verify .NET SDK availability at startup
- TOOLS-03: Graceful fallback when tools missing

## Implementation

### 1. Extract Core Logic into Shared Service

Create `ScanService.cs` in InfoExeGui project that directly calls the scan/analyze logic (previously in InfoExeApp/Program.cs):

```csharp
// src/InfoExeGui/ScanService.cs
public class ScanService
{
    // Directly embed the scan pipeline: classify → metadata → vendor → decompile
    // Uses System.Reflection, Microsoft.Data.Sqlite, Process (for ILSpy)
    public async Task<ScanResult> RunScanAsync(string rootPath, string dbPath, 
        string programName, string searchPath, bool includePython,
        IProgress<ScanProgress> progress)
}
```

Key changes from CLI:
- All `Console.WriteLine` → callback to GUI for live output
- All static methods become instance methods on ScanService
- Progress reporting via `IProgress<ScanProgress>` (files processed / total)

```csharp
// Instead of Console.WriteLine:
private void LogOutput(string message, bool isError = false)
{
    Dispatcher.UIThread.Post(() =>
    {
        OutputBox.Text += (isError ? "[ERR] " : "") + message + "\n";
        OutputBox.CaretIndex = OutputBox.Text.Length;
    });
}
```
